1. Prompt: Fix Selection & Multi-Move Functionality

Improvement Prompts:

Decouple Creation from Selection: Modify the DrawingController's mouseReleased method. When a new shape is created (e.g., after drawing a rectangle), do not automatically set it as the selected shape. Creating a shape and selecting a shape must be two separate actions. Selection should only happen when the "Select" tool is active.

Rewrite Hit-Detection Logic: Overhaul the search method in SearchService.java. The new logic must:

Find the Top-Most Shape: Iterate through the shape list backwards (from last-drawn to first-drawn) and stop as soon as you find the first shape under the mouse cursor.

Handle Single-Click (Deselect All): If the user clicks on a shape without holding the Ctrl key, first deselect all shapes in the drawing, then select only the new shape that was clicked.

Handle Multi-Click (Toggle): If the user is holding the Ctrl key and clicks a shape, simply toggle that one shape's selection state (selected -> unselected, or unselected -> selected) without affecting any other shapes.

Handle Empty-Space Click: If the user clicks on an empty part of the canvas (and is not holding Ctrl), deselect all shapes.

2. Prompt: Eliminate Lag & Delays for a Faster UI
Problem: The application feels slow because you are repainting the entire canvas on every single mouse movement during a drag (move, scale, or draw). This is extremely inefficient.

Improvement Prompt:

Implement "Dirty Rectangle" Repainting: Modify the mouseDragged method in DrawingController.java.

Instead of calling drawingView.repaint(), get the shape's position before you move or scale it (the "old bounds").

After you update the shape's position, get its "new bounds."

Call the specific repaint(Rectangle r) method twice: once for the oldBounds and once for the newBounds.

This tells Swing to only repaint those two small areas of the screen, which is thousands of times faster than repainting everything.

3. Prompt: Fix Misplaced Text Handles
Problem: You are correct, the selection handles (the 8 squares) on a Text shape are misplaced. This is because TextRenderer.java draws the string using the y coordinate as the text baseline, but the ShapeRenderer superclass draws the handles assuming y is the top-left corner.

Improvement Prompt:

Align the Graphics Context: In TextRenderer.java, right before you call super.render() (the line that draws the handles), you must temporarily "move" the canvas for the superclass.

Get the font's "ascent" (the height above the baseline) using FontMetrics.

Translate the Graphics2D object up by that ascent amount (e.g., g2.translate(0, -ascent)).

Call super.render().

Crucially, translate the graphics back down (g2.translate(0, ascent)) so the next shape renders correctly.

This will trick the ShapeRenderer into drawing the handles in the correct visual location, aligned with the top of the text.
